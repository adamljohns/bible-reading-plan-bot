How to Train Your Own Private ChatGPT for ~$100 Using Karpathy's nanochat (Complete Beginner's Guide)

By Adam "MOOP" Johns · U.S.M.C. Ministries · July 2, 2026 · General

You don't need billions of dollars to train your own ChatGPT. You need about $100, one weekend, and a willingness to copy-paste some commands.

I spent ~$100 and a single weekend training a ChatGPT-style model from scratch on my own notes, my own writing, and my exported AI chats. It now answers in my voice and recalls my ideas — with no API key, no subscription, and no rented brain in the cloud judging my every prompt.

This is the guide I wish I'd had: every command, every code change, and plain-English explanations of the jargon so you don't get stuck halfway and rage-quit.

If you've never trained a model before, you are exactly who I wrote this for. Take it one step at a time. You've got this. 🚀

⚠️ A quick, honest disclaimer. "You don't need billions to train the next ChatGPT" is a hopeful, deliberately hyperbolic statement. The capital expense to train true frontier models today is genuinely enormous. But the cost of compute keeps falling, and what you can do right now for under $100 is real, useful, and yours. This is a build, not a flex. Treat it that way and you'll be delighted.

The 60-Second Mental Model

Training a chatbot happens in two big phases. Keep these two straight and everything else in this guide will make sense.

Phase 1 — Pretraining → produces the base model

The model reads a huge pile of internet text and learns exactly one skill: predict the next word. That's it. By getting really, really good at "what word comes next," it absorbs grammar, facts, and a surprising amount of reasoning.

  • This is the expensive part (your ~3 hours of GPU time).
  • The result talks like the internet. It can continue text, but it can't chat yet. Ask it a question and it might just write more questions.

Phase 2 — Fine-tuning (SFT) → produces the chat model

You show the base model thousands of example conversations so it learns to behave like a helpful assistant — to answer instead of autocomplete.

  • This is cheap and fast (minutes, not hours).
  • This is where your personal data goes in. 🎯

🔑 Analogy: Pretraining is sending the model to school to learn language and how the world works. Fine-tuning is the apprenticeship, where it learns one specific job — in our case, being your second brain.

The Optional Phase 3 — RL (Reinforcement Learning)

There's an optional third phase, RL, that sharpens narrow skills like math by rewarding good answers and punishing bad ones. We'll skip it for the main build and mention it again at the very end. You do not need it to get a delightful personal chatbot.

Words You'll Keep Seeing (Quick Hits)

Don't memorize these — there's a full glossary at the bottom. But here are the big ones up front so nothing feels like alphabet soup:

  • GPU — the specialized chip that does the heavy math. Training needs powerful ones (H100s). You rent them by the hour.
  • Token — a chunk of text (a word or word-piece). Models read and write tokens, not letters.
  • Tokenizer — the tool that chops text into tokens. You train one first.
  • Parameters — the model's "knobs": the numbers it learns. More parameters = bigger, smarter, slower model.
  • Depth — nanochat's single dial for model size: the number of layers. Bigger depth = bigger model.
  • Batch / batch size — how many examples the model looks at before it updates itself.
  • Checkpoint — a saved copy of the model's weights on disk. Your "save file."
  • Loss — a single number measuring how wrong the model is. Training's whole job is to drive this down.

The Tool: nanochat

We're using nanochat, an open-source project by Andrej Karpathy (co-founder of OpenAI, former Director of AI at Tesla, and the internet's favorite ML teacher).

It's ~8,000 lines of clean, readable PyTorch that covers the entire pipeline — tokenizer, pretraining, fine-tuning, RL, inference, and a web chat UI — and it's designed to run start-to-finish on one machine.

Why it's perfect for a first-time builder:

  • 🎛️ One dial. You set --depth (how many layers) and nanochat automatically computes every other setting for you.
  • 📖 Readable. No giant, intimidating configuration system to fight.
  • 💸 Cheap. GPT-2-grade capability for around $100.

Before You Spend a Single Dollar: Do a Free Dry Run

🔑 I strongly recommend this. Do not skip it.

Before renting any GPUs, run the whole pipeline once with a tiny model on your own laptop. Nothing teaches you the shape of the process like watching it happen end-to-end. You'll make your beginner mistakes here, where they cost 0 * *insteadof * *10/hour.

⚠️ nanochat is built for NVIDIA CUDA GPUs. On a laptop (Mac/Apple Silicon or a plain CPU) you can't do a real run — but you can do a tiny smoke test to learn the commands, file layout, and flow. Expect it to be slow and the output to be gibberish. That's fine — the goal is familiarity, not quality.

Dry Run on Mac (Apple Silicon) or CPU

# 1. Get the code
git clone https://github.com/karpathy/nanochat.git
cd nanochat

# 2. Install uv (the fast Python package manager nanochat uses)
curl -LsSf https://astral.sh/uv/install.sh | sh

# 3. Create the environment and install dependencies (CPU/Mac build of PyTorch)
uv sync --extra cpu
source .venv/bin/activate

# 4. Train a tiny tokenizer on a small slice of text
python -m scripts.tok_train --max-chars=100000000

# 5. Pretrain a TINY base model (depth=2 is a toy; it WILL be dumb — that's the point)
python -m scripts.base_train -- --depth=2 --device-batch-size=1

# 6. Fine-tune it
python -m scripts.chat_sft -- --device-batch-size=1

# 7. Chat with your toy model in the terminal
python -m scripts.chat_cli

💡 What just happened? You ran the exact same pipeline you'll run on the rented GPU, just shrunk down. When you do the real run, the only things that change are: a bigger --depth, more data, and 8 GPUs instead of your laptop. The muscle memory you build here is worth its weight in gold.

The Real Build

⚠️ nanochat is a fast-moving repo. The commands below are current as of this writing, but Karpathy iterates often — flag names, the dataset, and the exact "speedrun" depth do change. If a command errors, open the repo's README.md and runs/speedrun.sh; they're the source of truth and always show the latest canonical run.

Step 1: Rent and Connect to a GPU Box

Spin up an 8×H100 instance from your provider of choice. Pick an Ubuntu image with CUDA pre-installed (every provider above offers one). Then SSH in:

# Your provider gives you the IP address and an SSH command — it'll look like this:
ssh ubuntu@<YOUR_GPU_IP>

Once you're in, confirm the GPUs are actually there:

nvidia-smi

💡 What just happened? nvidia-smi ("NVIDIA System Management Interface") lists your GPUs. You should see 8 × H100 with ~80 GB of memory each. If you see them, your rented "engine" is running. If you don't, stop and fix this before spending money on training.

⚠️ The meter is running now. From this moment you're paying by the hour. Stay focused — and don't forget Step 12 (shut down the box) when you're done.

Step 2: Install nanochat

git clone https://github.com/karpathy/nanochat.git
cd nanochat

# Install uv, the fast package manager
curl -LsSf https://astral.sh/uv/install.sh | sh

# Build the environment and install everything (GPU build of PyTorch)
uv sync --extra gpu
source .venv/bin/activate

💡 Why this matters: uv sync reads nanochat's dependency list and installs PyTorch and friends into a clean, isolated .venv. The --extra gpu picks the CUDA build of PyTorch (use --extra cpu on a laptop). source .venv/bin/activate "steps into" that environment so the python you run is the right one. If a later command can't find a package, 9 times out of 10 you forgot to activate after reconnecting.

Step 3: Know Where Things Live

nanochat keeps everything it produces in one tidy place:

~/.cache/nanochat/
├── tokenizer/                  # your trained tokenizer
├── base_data_climbmix/         # downloaded internet training text (ClimbMix shards)
├── base_checkpoints/<tag>/     # base-model checkpoints (after pretraining)
├── chatsft_checkpoints/<tag>/  # fine-tuned chat checkpoints  ← your personal model lands here
├── chatrl_checkpoints/<tag>/   # (only if you do the optional RL phase)
└── identity_conversations.jsonl

🔑 Bookmark this path. When you "save your model" in Step 12, this folder — specifically ~/.cache/nanochat/chatsft_checkpoints/ — is the treasure you're carrying home. (<tag> is an auto-generated model name like d24.)

💡 Heads-up: you can point this whole cache somewhere else with the NANOCHAT_BASE_DIR environment variable — worth knowing if your boot disk is small and your data lives on a bigger mounted volume.

Step 4: Download the Training Data

For pretraining, nanochat reads shards of high-quality web text — the ClimbMix dataset (NVIDIA's ClimbMix, repackaged and shuffled, from Hugging Face karpathy/climbmix-400b-shuffle). Each shard is a parquet file of ~250M characters. Download them with one command:

# Downloads the pretraining text shards into ~/.cache/nanochat/base_data_climbmix
python -m nanochat.dataset -n 170

💡 What just happened? -n 170 pulls 170 shards of internet text — about what a depth-24 model needs (~150), plus a little padding. This is the "huge pile of text" the base model will read to learn language. It's a big download, so let it finish before moving on.

Step 5: Train the Tokenizer

Before the model can read text, you need a tokenizer to chop text into tokens.

python -m scripts.tok_train

# (Optional but nice) check how well it compresses text
python -m scripts.tok_eval

💡 tok_train already defaults to ~2 billion characters of training text — no flag needed. (If you ever want to override it, the flag is --max-chars.)

💡 Why this comes first: The model only ever sees tokens, never raw letters. The tokenizer is the translator between human text and the model's number-language. Train it once, up front, and everything downstream uses it.

Step 6: Pretrain the Base Model

This is the big one — the ~3 hours of GPU time that turns a pile of internet text into a model that understands language.

Because it takes hours, run it inside a screen session so it keeps going even if your SSH connection drops:

# Start a detachable session named "train"
screen -S train

# Inside that session, launch training across all 8 GPUs:
torchrun --standalone --nproc_per_node=8 -m scripts.base_train -- \
  --depth=24 --target-param-data-ratio=8 --device-batch-size=16 --fp8

To leave it running and reclaim your terminal: press Ctrl-A then D (for detach). To come back and check on it later: screen -r train.

💡 Decoding that command:

  • torchrun — PyTorch's launcher for using multiple GPUs at once.
  • --nproc_per_node=8 — "use all 8 GPUs."
  • -m scripts.base_train — run the pretraining script.
  • -- — separates torchrun's own options from the script's options (nanochat's current convention — keep it).
  • --depth=24 — the one dial. Depth 24 is the reference "speedrun" size: GPT-2-grade, ~3 hours on 8×H100, roughly 50–75. nanochat computes every other setting (width, learning rate…) from this single number. Bump it to 26 for a bit more capability and cost.
  • --target-param-data-ratio=8, --fp8, --device-batch-size=16 — the speedrun's tuned settings for a fast, cheap run. You can safely copy them as-is.

🔑 Watch the loss number. It starts high and should steadily fall. A falling loss means the model is learning. This is the most satisfying number you'll watch all weekend.

⚠️ CUDA out of memory? Lower --device-batch-size (try 8, then 4, then 2). See Troubleshooting.

💡 What just happened? You now have a base model in ~/.cache/nanochat/base_checkpoints/. It "talks like the internet." Next, we make it talk like you. This is where the fun begins.

(If you followed older nanochat guides that had a separate mid_train step — that stage has been folded into fine-tuning, so there's nothing extra to run here. Straight on to your data.)

🎯 Step 7: Prepare YOUR Data (This Is Where the Magic Happens)

🔑 This is the heart of the whole project. Pretraining gave you a generic brain. This step gives it your memories, your voice, and your identity. Spend real care here — the quality of your final model is mostly decided by the quality of the data you feed it now.

We'll prepare three kinds of personal data, and they each do a different job:

Data type What it teaches the model Format
A. Exported chats How you talk and ask questions; your style Conversations
B. Notes → Q&A pairs Your knowledge and ideas (recall) Question/Answer conversations
C. Identity / persona Who it is — its name, that it's yours Short scripted conversations

The fine-tuning data is just a list of conversations, where each conversation is a list of {"role": "...", "content": "..."} messages. We'll produce a JSONL file (one JSON conversation per line) for each type.

💡 What's JSONL? "JSON Lines" — a plain text file where each line is a complete JSON object. It's the standard format for training data because you can stream it line-by-line without loading the whole file. One conversation per line.

7A. Export Your Chats → JSONL

If you've used ChatGPT, you can export your whole history: Settings → Data Controls → Export Data. You'll get a conversations.json file by email. This is gold — it's thousands of examples of how you actually talk.

Save this script as prepare_chats.py inside the nanochat folder:

# prepare_chats.py — convert a ChatGPT export into nanochat SFT conversations
import json

# Path to the conversations.json from your ChatGPT data export
SRC = "conversations.json"
OUT = "my_chats.jsonl"

def walk_mapping(mapping):
    """ChatGPT stores messages as a tree; flatten it to an ordered list."""
    # Find the root, then follow children in order
    msgs = []
    # Build id -> node, find the node with no parent
    nodes = mapping
    # Collect messages that have content
    ordered = sorted(
        (n for n in nodes.values() if n.get("message")),
        key=lambda n: (n["message"].get("create_time") or 0),
    )
    for n in ordered:
        m = n["message"]
        role = m.get("author", {}).get("role")
        parts = m.get("content", {}).get("parts", [])
        text = "".join(p for p in parts if isinstance(p, str)).strip()
        if role in ("user", "assistant") and text:
            msgs.append({"role": role, "content": text})
    return msgs

with open(SRC) as f:
    data = json.load(f)

count = 0
with open(OUT, "w") as out:
    for convo in data:
        messages = walk_mapping(convo.get("mapping", {}))
        # Keep only real back-and-forths (at least one user + one assistant turn)
        if sum(1 for m in messages if m["role"] == "user") >= 1 and \
           sum(1 for m in messages if m["role"] == "assistant") >= 1:
            out.write(json.dumps({"messages": messages}) + "\n")
            count += 1

print(f"Wrote {count} conversations to {OUT}")

Run it:

python prepare_chats.py

💡 What just happened? You turned your messy export into clean training conversations. The model will learn your question style, your follow-ups, and the kinds of answers you find satisfying. Even your typos teach it something about your voice.

⚠️ Privacy gut-check. Open my_chats.jsonl and skim it. This is the moment to delete anything you don't want baked into a model forever — passwords, other people's private info, that one 3 a.m. conversation. Once it's trained in, it's in.

7B. Turn Your Notes → Q&A Pairs

Raw notes (Obsidian, Apple Notes, a journal.md, whatever) are great knowledge but a bad format — the model learns to chat, so it needs your knowledge shaped as questions and answers.

The simplest reliable approach is one Q&A per note or per chunk. Save this as prepare_notes.py:

# prepare_notes.py — turn a folder of .md/.txt notes into Q&A conversations
import json, os, glob

NOTES_DIR = "my_notes"     # put your .md / .txt files here
OUT = "my_notes.jsonl"

def chunk(text, size=1500):
    """Split long notes into digestible chunks."""
    text = text.strip()
    return [text[i:i+size] for i in range(0, len(text), size)] or [text]

count = 0
with open(OUT, "w") as out:
    for path in glob.glob(os.path.join(NOTES_DIR, "**/*.*"), recursive=True):
        if not path.endswith((".md", ".txt")):
            continue
        title = os.path.splitext(os.path.basename(path))[0]
        with open(path, errors="ignore") as f:
            body = f.read()
        for piece in chunk(body):
            if not piece.strip():
                continue
            convo = {"messages": [
                {"role": "user",
                 "content": f"What do my notes say about {title}?"},
                {"role": "assistant",
                 "content": piece.strip()},
            ]}
            out.write(json.dumps(convo) + "\n")
            count += 1

print(f"Wrote {count} Q&A conversations to {OUT}")
mkdir my_notes        # drop your .md / .txt notes in here
python prepare_notes.py

🔑 Want higher-quality Q&A? Instead of the mechanical "What do my notes say about X?" template, you can use a bigger LLM (via an OpenRouter API key) to read each note and generate natural question/answer pairs from it. That produces a much smarter recall model — but the simple template above works and costs nothing. Start simple; upgrade later.

💡 Why questions and answers? Your finished model is a chat model. It only knows how to respond when something looks like a conversation. By wrapping each note as "question → your knowledge," you're teaching it to surface that knowledge when you ask. Raw notes pasted in as-is would just teach it to ramble.

7C. Give It an Identity / Persona

This is the cherry on top: a small set of hand-written conversations that tell the model who it is. This is what makes it feel like yours instead of a generic assistant. Write 20–50 of these by hand. Save as my_identity.jsonl:

{"messages": [{"role": "user", "content": "Who are you?"}, {"role": "assistant", "content": "I'm your personal AI — a private second brain trained on your notes, your writing, and your chats. I'm not ChatGPT and I don't phone home to anyone. I'm yours."}]}
{"messages": [{"role": "user", "content": "What's your name?"}, {"role": "assistant", "content": "You can call me whatever you like — I was built to be your personal assistant, running entirely on hardware you control."}]}
{"messages": [{"role": "user", "content": "Who made you?"}, {"role": "assistant", "content": "You did — by fine-tuning Karpathy's nanochat on your own data over a weekend. I run privately, with no API and no subscription."}]}
{"messages": [{"role": "user", "content": "Are you ChatGPT?"}, {"role": "assistant", "content": "Nope. I'm a small, private model you trained yourself. I'm humbler than ChatGPT, but I know your stuff and I never leave your machine."}]}

🔑 Write these in the voice you want back. If you want a warm, encouraging assistant, write warm, encouraging answers. If you want it terse and dry, write it terse and dry. The model becomes the average of what you show it — so show it the personality you actually want to talk to.

💡 Why so few examples can work: Identity facts are short, consistent, and (in the next step) we'll oversample them so they punch far above their tiny size. A few dozen crisp identity lines, repeated, reliably teach the model who it is.

Step 8: Inject Your Data Into Fine-Tuning (The Critical Edit)

⚠️ This is the single most important code change in the whole guide. Get this right and your model is yours. Skip it and you just trained a generic GPT-2. Read slowly.

By default, scripts/chat_sft.py fine-tunes on a mixture of tasks — public instruction data (SmolTalk), a bit of multiple-choice and math (MMLU, GSM8K), spelling drills, and an identity file — so the model learns general assistant behavior. We're going to add your three JSONL files to that mixture — and oversample them.

Why "oversample"? (The most important concept here)

Your personal data is tiny compared to the public datasets — maybe a few thousand lines next to hundreds of thousands. If you just toss it in once, it's a drop in the ocean: the model will barely notice it and won't sound like you at all.

Oversampling means repeating your data many times so it makes up a meaningful fraction of what the model sees during fine-tuning. Show your identity file 50 times and your notes 10 times, and suddenly your voice and your facts carry real weight.

🔑 Analogy: If you want someone to remember your name at a party of 10,000 strangers, you don't say it once. You say it 50 times. Oversampling is saying your name 50 times.

⚠️ Goldilocks warning. Too little oversampling → the model ignores your data. Too much → it overfits: it parrots your files word-for-word and forgets how to handle anything new. Start with the multipliers below, then tune. Identity can be oversampled the most (it's tiny and you want it rock-solid). Chats/notes need less.

First, put your data where the box can find it

Copy your three JSONL files (my_chats.jsonl, my_notes.jsonl, my_identity.jsonl) into a folder on the GPU box — say ~/nanochat_personal/.

💡 Format check: each of these is JSONL with {"messages": [...]} per line — exactly the shape nanochat's own identity file uses, so it drops right in.

The Edit

Open scripts/chat_sft.py and find the block that builds the task list. It looks roughly like this (a plain Python list named train_tasks, wrapped in a TaskMixture):

# ... existing code in scripts/chat_sft.py ...
train_tasks = [
    SmolTalk(split="train"),
    CustomJSON(filepath=identity_conversations_filepath),
    CustomJSON(filepath=identity_conversations_filepath),
    MMLU(subset="all", split="auxiliary_train"),
    GSM8K(subset="main", split="train"),
    # ...spelling tasks...
]
train_dataset = TaskMixture(train_tasks)   # <-- your data must be in the list BEFORE this line

See how the identity file is already loaded with CustomJSON — and listed twice (that's nanochat oversampling its own identity data ×2)? That's your hook. Add your files the exact same way, right before the TaskMixture(...) line:

# --- ADD your personal data to train_tasks (before TaskMixture is built) ---
import os
PERSONAL = os.path.expanduser("~/nanochat_personal")

# Each CustomJSON entry = one pass over the file. Listing it N times = oversampling ×N.
train_tasks += [CustomJSON(filepath=f"{PERSONAL}/my_chats.jsonl")    for _ in range(3)]   # your voice
train_tasks += [CustomJSON(filepath=f"{PERSONAL}/my_notes.jsonl")    for _ in range(10)]  # your knowledge
train_tasks += [CustomJSON(filepath=f"{PERSONAL}/my_identity.jsonl") for _ in range(50)]  # who it is
print(f"[personal] train_tasks now has {len(train_tasks)} tasks")

🔑 This is oversampling, done the nanochat way. You're not copying data by hand — you're adding the same task to the list multiple times. range(50) on your identity file means the model sees it 50 times per epoch. That's how a few dozen identity lines end up carrying real weight. (CustomJSON and os are the only names you touch; CustomJSON is already imported at the top of the file since the stock identity data uses it.)

💡 What just happened? You blended your personal conversations into the public fine-tuning mix, weighted by how strongly you want each one to land. The model still learns good general assistant manners from SmolTalk/MMLU/GSM8K — and it learns your voice, your knowledge, and its identity from yours.

🔑 nanochat evolves — adapt, don't panic. The repo moves fast, so the exact task names in train_tasks may shift between versions. The concept never changes: find the train_tasks list, add CustomJSON(filepath=...) entries for your files, and repeat each entry to oversample. If train_tasks has been renamed, just look for the list that gets wrapped in TaskMixture(...) and splice yours in there.

Step 9: Run the Fine-Tune

This is the fast, cheap, magical part — minutes, not hours.

First, one small prerequisite: the stock task list expects nanochat's default identity file to exist, so grab it once (it lives next to your other cache data):

curl -L -o "$NANOCHAT_BASE_DIR/identity_conversations.jsonl" \
  https://karpathy-public.s3.us-west-2.amazonaws.com/identity_conversations.jsonl

💡 NANOCHAT_BASE_DIR defaults to ~/.cache/nanochat — if you never set it, use that path directly.

Then run the fine-tune:

torchrun --standalone --nproc_per_node=8 -m scripts.chat_sft -- --device-batch-size=16

💡 What just happened? nanochat took your base model and nudged every parameter toward answering like an assistant — specifically, like the assistant you described in your data. When the loss settles, you've got a personal chat model sitting in ~/.cache/nanochat/chatsft_checkpoints/. This is the moment it becomes yours. 🎉

⚠️ If it crashes with CUDA out of memory, lower --device-batch-size (try 8, then 4, then 2, then 1).

Step 10 (Optional): Bake In Hard Facts

If there are facts you want the model to know cold — your address, your project names, key dates, definitions — write them as extra Q&A pairs in a my_facts.jsonl and add one more heavily-oversampled CustomJSON line in Step 8, e.g.:

train_tasks += [CustomJSON(filepath=f"{PERSONAL}/my_facts.jsonl") for _ in range(30)]

This is optional, but it's a cheap way to make recall on your most important facts much more reliable.

⚠️ Don't go overboard. Oversample a fact too hard and the model will blurt it out at unrelated moments. A handful of high-value facts at a moderate multiplier is the sweet spot.

Step 11: Talk to Your Second Brain

Two ways to chat with your finished model.

Option A — Command-Line Chat (fastest)

python -m scripts.chat_cli

Type a message, hit enter, and there it is — your model, answering in your voice. Try:

  • "Who are you?" → it should give you the identity you wrote.
  • "What do my notes say about <one of your topics>?" → recall in action.

Option B — The ChatGPT-Style Web UI (the fun one)

python -m scripts.chat_web

This starts a web server on the GPU box (usually on port 8000). To see it in your browser, open an SSH tunnel from your laptop so the box's port shows up locally:

# Run this on YOUR laptop, in a new terminal:
ssh -L 8000:localhost:8000 ubuntu@<YOUR_GPU_IP>

Then visit http://localhost:8000 in your browser. You'll get a clean, ChatGPT-style chat page talking to your private model. 🥳

💡 What's an SSH tunnel? It's a secure pipe that makes a port on the remote box appear as the same port on your laptop. -L 8000:localhost:8000 means "forward my local 8000 to the box's 8000." Now localhost:8000 in your browser is really the model running in the cloud.

⚠️ Nothing loads? Make sure the chat_web server is actually running on the box, that the tunnel command is running on your laptop, and that you're using the same port in all three places (server, tunnel, browser). See Troubleshooting.

Step 12: Save Your Model — Then SHUT DOWN the Box

⚠️ DO NOT SKIP THIS. The box is deleted when you terminate it, and you're paying every minute it's alive. Get your model off the box, then kill it.

1. Copy your trained model to your laptop. Run this on your laptop:

# Pull the fine-tuned model (and tokenizer) down to your machine
mkdir -p ~/nanochat-model
scp -r ubuntu@<YOUR_GPU_IP>:~/.cache/nanochat/chatsft_checkpoints ~/nanochat-model/
scp -r ubuntu@<YOUR_GPU_IP>:~/.cache/nanochat/tokenizer ~/nanochat-model/

🔑 The chatsft_checkpoints folder is your trained model. Guard it like the weekend's work it represents. Back it up somewhere safe.

2. Terminate the instance. Do this in your cloud provider's dashboard — click Terminate / Delete on the instance. (Stopping nvidia-smi or closing SSH does not stop billing.) Confirm in the dashboard that the instance is gone, then check that no surprise charges are accruing.

💸 The #1 way beginners lose money here is leaving an 8–24/hour box running overnight. Set a phone reminder. Terminate it. Verify it's dead.

Troubleshooting

CUDA out of memory (OOM) The model + batch don't fit in GPU memory. Lower the per-GPU batch: set --device-batch-size=8 (then 4, then 2, then 1) on your base_train / chat_sft command. Smaller batches train a bit slower but fit. If still stuck, lower --depth.

My SSH connection dropped and training stopped. You forgot screen (or tmux). Always launch long jobs inside screen -S train, detach with Ctrl-A then D, and reattach with screen -r train. Next time the connection drops, the job keeps running.

command not found / No module named ... after reconnecting. You're not in the virtual environment. Run cd nanochat && source .venv/bin/activate after every fresh SSH login.

The web UI won't load in my browser. Three things must all be true: (1) python -m scripts.chat_web is running on the box; (2) the SSH tunnel ssh -L 8000:localhost:8000 ... is running on your laptop; (3) the port number matches in all three spots. If 8000 is taken, pick another (e.g. 8001) and use it everywhere.

nvidia-smi shows fewer than 8 GPUs (or none). Your instance didn't come up right. Don't train — you'll waste money. Terminate it and relaunch, making sure you selected an 8×H100 node with a CUDA image.

The model is dumb / generic / doesn't sound like me. Almost always an oversampling problem. Increase the range(...) multipliers in Step 8 (especially identity and notes), and make sure your CustomJSON lines are actually being added before the TaskMixture(train_tasks) line. The print(f"[personal] train_tasks now has {len(train_tasks)} tasks") should show a much bigger number than the stock list.

The model parrots my notes word-for-word and can't generalize. The opposite problem: you over-oversampled, and it overfit. Lower your multipliers and/or fine-tune for fewer steps.

Loss isn't going down / is NaN. A NaN loss usually means the learning rate is too high for your setup or data is malformed. Trust nanochat's auto-computed defaults for your --depth first; if you hand-tuned settings, revert them. Double-check your JSONL files are valid (one JSON object per line, with a messages key).

Glossary (Plain English)

  • Base model — the model right after pretraining. Knows language and facts, but autocompletes instead of chatting.
  • Batch / batch size — how many examples the model studies before updating its knobs. Bigger = faster but more memory.
  • Checkpoint — a saved snapshot of the model's weights on disk. Your "save file."
  • CUDA — NVIDIA's software for running math on their GPUs. nanochat needs it for the real run.
  • Depth — nanochat's one dial: the number of layers. More depth = bigger, smarter, slower, pricier model.
  • Fine-tuning (SFT) — "Supervised Fine-Tuning." Teaching the base model to chat by showing it example conversations. Where your data goes.
  • GPU — the chip that does the training math. You rent powerful ones (H100s) by the hour.
  • H100 — a top-tier NVIDIA data-center GPU. You'll rent 8 of them.
  • JSONL — "JSON Lines." A text file with one complete JSON object per line. The standard training-data format.
  • Loss — a number measuring how wrong the model is. Training drives it down. Watch it fall.
  • Oversampling — repeating your (small) personal data many times so it carries real weight against the huge public datasets.
  • Overfitting — when a model memorizes its training data instead of learning from it. The result of too much oversampling.
  • Parameters — the millions of numbers ("knobs") the model learns. More = bigger and (usually) smarter.
  • Pretraining — phase 1: the model reads tons of text and learns to predict the next word. The expensive part.
  • RL (Reinforcement Learning) — optional phase 3: sharpening narrow skills (like math) via rewards. We skip it here.
  • Token — a chunk of text (word or word-piece). The unit models actually read and write.
  • Tokenizer — the tool that splits text into tokens. You train it first.
  • torchrun — PyTorch's launcher for training across multiple GPUs at once.
  • uv — a fast Python package manager nanochat uses to set up its environment.
  • screen / tmux — tools that keep a terminal session (and your training job) alive even if your SSH connection drops.

The Whole Thing, Copy-Paste

Here's the entire real run, start to finish, for quick reference:

# --- On the GPU box ---
ssh ubuntu@<YOUR_GPU_IP>
nvidia-smi                                    # confirm 8x H100

git clone https://github.com/karpathy/nanochat.git

screen -S train                               # detachable session

  --depth=24 --target-param-data-ratio=8 --device-batch-size=16 --fp8
# (Ctrl-A then D to detach; screen -r train to return)

# --- Prepare YOUR data (see Step 7) ---

python prepare_notes.py                       # -> my_notes.jsonl
# hand-write my_identity.jsonl

# --- Edit scripts/chat_sft.py to add CustomJSON + oversample your data (Step 8) ---
curl -L -o "$NANOCHAT_BASE_DIR/identity_conversations.jsonl" \
  https://karpathy-public.s3.us-west-2.amazonaws.com/identity_conversations.jsonl

# --- Talk to it ---
